# Invariant rider lexicon — implementation register

**Date:** 2026-08-02  
**Parent pull request:** #24  
**Status:** Architecture binding; lexical research, selection, governance, and implementation pending.

## Governing determination

Caeluviim uses one invariant rider lexicon across every host language.

```text
same rider lexicon
+ different host-language grammar
→ same canonical protocol nomenclature
```

The rider does not select a different foreign word relative to each host language. It replaces the same central host-language concept words in every language with the same canonical rider lexemes.

## Lexical strata

### Core stratum

The most central protocol terms are preferentially sourced from lost, dormant, sleeping, extinct, endangered, severely displaced, and historically suppressed languages.

### Compositional stratum

Less-central and derivative terms may be governed compounds or derivations assembled from the accumulated multilingual rider lexicon, operators, and glyph structures.

Every composite must preserve component identity, source provenance, semantic contribution, and protocol-coinage status. No composite may be represented as a naturally inherited word of a contributing language.

- define distinction among attested, revived, reconstructed, protocol-coined, and multilingual-composite terms;

### Phase 2 — lexical candidate records

For each conception, assemble source-bound candidates containing:

- exact form and script;
- language, community, region, and period;
- pronunciation;
- morphology;
- etymology;
- attested meanings and contexts;
- semantic history;
- source manifestations and exact citation locations;
- use restrictions and community authority;
- relation and non-equivalence to the Caeluviim conception;
- uncertainties, objections, and alternatives.

### Phase 3 — dyadic selection and governance

- compare candidates without flattening semantic differences;
- identify the contribution each candidate would make to the conception;
- preserve competing candidates;
- record assent, objection, constraints, and selection basis;
- ratify one invariant rider lexeme or an explicitly governed multi-anchor construction.

### Phase 4 — full implementation

Implement the selected rider term in:

- human-readable card;
- machine-readable Definition Claim record;
- nested lexical and multilingual graphs;
- canonical Claim and lexeme maps;
- parser and identifier resolution;
- model-access packets;
- search and interface display;
- transliteration and pronunciation support;
- glyph/emoji-rider relation;
- provenance and governance manifests;
- validation and round-trip tests.

### Phase 5 — compositional secondary lexicon

After the core lexicon stabilizes:

- define the permitted component inventory;
- define affixes, operators, ordering, attachment, and semantic-composition rules;
- define phonological and orthographic accommodation;
- construct derivative terms from existing rider elements;
- preserve every component's source and semantic contribution;
- validate reconstruction from component Claims;
- declare every constructed form as a protocol coinage or multilingual composite.

## Constitutional formulation

> Caeluviim's rider is one stable translingual lexicon, not a separate translation layer for each language. It replaces the same central vocabulary in every host language. Its core lexemes are preferentially sourced from lost, dormant, endangered, displaced, and historically suppressed languages; its less-central vocabulary may be composed from the accumulated multilingual rider field. Host-language words remain glosses and access paths, while the invariant rider carries canonical protocol nomenclature across every linguistic environment.
